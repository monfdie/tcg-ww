# Виртуальные ставки

Модуль использует текущие Express / EJS / Mongoose и существующую Discord-сессию. События ставок не связаны с `Match`, комнатами, драфтами или турнирами. Новых npm-зависимостей нет.

## Запуск

После обновления файлов перезапустите приложение (`npm start`). Используется существующий `MONGO_URI`. Требуется MongoDB replica set или Atlas с транзакциями; при неподдерживаемой конфигурации операции ставок недоступны, остальные маршруты продолжают работать. Настроенная база проверена на поддержку транзакций.

Коллекции и уникальные индексы создаются автоматически. Фоновая задача каждые 10 секунд закрывает события, продолжает незавершённые расчёты и создаёт кошельки для зарегистрированных пользователей (порциями по 20). При первом посещении раздела авторизованный пользователь получает кошелёк сразу. Начальный баланс выдаётся ровно один раз. При большом числе существующих аккаунтов первичное заполнение рейтинга занимает несколько циклов задачи.

## Страницы

- `/bets`: текущие события и получение недельного бонуса.
- `/bets/mine`: история ставок с фильтрами и последние 30 операций баланса.
- `/bets/leaders`: топ-10 и собственное место.
- `/bets/admin`: компактный список событий; только администратору доступны число ставок, общая сумма, распределение по сторонам и кнопка View bets.
- `/bets/admin/event/:id/bets`: все ставки события, включая скрытые из личной истории: игрок и Discord ID, дата, сторона, сумма, зафиксированный коэффициент, статус и выплата. По 30 строк на страницу.
- `/bets/admin/points`: поиск по части ника (без учёта регистра) или точному Discord ID, выбор игрока с аватаром и доступным балансом, начисления, списания и настройки баллов.

Администратор определяется существующими `ADMIN_DISCORD_ID` или `User.role === 'admin'`.

## Управление

1. Создайте черновик: название, описание, два различных участника, коэффициенты от 1 с точностью до двух десятичных знаков. Время закрытия необязательно; форма использует UTC+3, страницы показывают время UTC+3.
2. Опубликуйте событие. После публикации названия участников, название и описание фиксируются. До закрытия можно изменить коэффициенты для будущих ставок и срок закрытия.
3. Закройте приём вручную или дождитесь срока. Сервер отвергает ставки начиная с указанного времени независимо от задержки фоновой задачи.
4. Выберите победителя. Проверьте итоговую страницу с числом ставок и общей суммой выплат, отметьте подтверждение и отправьте результат. Результат после подтверждения неизменяем.
5. Для технической победы или отмены используйте «Отменить и вернуть ставки». Это отменяет всё событие, возвращая исходные суммы. Отменить рассчитанное событие нельзя.

## Правила баллов

- По умолчанию: 1000 на старте, 250 по кнопке раз в календарную неделю. Неделя начинается в понедельник в 00:00 фиксированного UTC+3, без сезонного перевода часов. Пропущенные бонусы не копятся.
- Настройки меняют будущие начисления; уже выданный стартовый баланс не пересчитывается.
- Админ выбирает игрока через поиск по нику или Discord ID. Начисление и списание требуют причины. Перед списанием показываются игрок, сумма, причина и баланс до/после; подтверждение действует 10 минут. Если баланс изменился, нужно повторно проверить списание. Сумма и игрок берутся из серверного подтверждения, а не из финальной формы.
- Удаление из истории доступно только администратору. Обычные пользователи не могут скрывать свои ставки, в том числе прямым запросом. Удаление завершённой ставки или завершённого/отменённого события требует отдельного экрана подтверждения. Удаление скрывает запись из истории, сохраняя балансы, выплаты, финансовые записи и доступ администратора к ставкам.
- Ставка — положительное целое число в пределах доступного баланса. Дополнительных игровых лимитов нет; технический предел — точные целые JavaScript (`Number.MAX_SAFE_INTEGER`).
- Можно добавлять ставки на одну выбранную сторону. Каждая имеет собственный зафиксированный коэффициент и округляется отдельно.
- Выплата включает исходную ставку: `floor(сумма × коэффициент)`. Вычисление производится через целые `BigInt`, без ошибок дробной арифметики. Проигрыш не возвращает ставку.
- Рейтинг: доступный баланс плюс незавершённые ставки, без потенциального выигрыша. При равенстве баллов место одинаковое; отображаются ровно 10 строк, порядок равных определяется ID пользователя.

## Надёжность

Списание, запись ставки и журнал проводятся в одной транзакции. Уникальные ключи защищают стартовый баланс, бонусы, ручные начисления и отправку ставок от повторов. Принятие ставки изменяет документ события, поэтому закрытие и изменение коэффициента сериализуются с приёмом ставок. Одну сторону фиксирует уникальная пара пользователь/событие.

Подтверждение результата фиксирует неизменяемое решение. Выплаты идут отдельными транзакциями для каждой ставки, порциями по 200 на событие за проход. После перезапуска обработка продолжается, завершённые ставки повторно не оплачиваются. Ошибки фоновой задачи видны в серверном логе `Betting maintenance`; событие остаётся в расчёте для повторной попытки. На время расчёта суммы обновляются по мере обработки ставок.

Все изменяющие запросы требуют Discord-сессию и CSRF-токен. Админские действия проверяют роль на сервере. Сумма, сторона, коэффициент, дедлайн и баланс проверяются сервером; клиентский предпросмотр выплаты носит информационный характер.

## Проверки

`npm test` запускает существующие проверки драфтов/авторизации/аватаров, правила ставок и рендер всех новых страниц.

Интеграционный тест запускается отдельно в PowerShell:

```powershell
$env:BETTING_INTEGRATION='1'
node --test --test-force-exit tests/betting-integration.test.cjs
Remove-Item Env:BETTING_INTEGRATION
```

Он использует `MONGO_URI`, но создаёт отдельную случайную базу с префиксом `betting_test_` и удаляет только её после проверки. Нужны права на создание и удаление этой временной базы. Рабочие данные приложения тест не изменяет.
